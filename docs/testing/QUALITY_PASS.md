# 実操作と画面キャプチャに基づく改善

2026-11-19 JST。模擬農場を使い、提出版 `f5f2256` と `feat/quality-pass` を比較した。

| 確認した症状 | 対応と回帰確認 |
|---|---|
| 390pxで候補生成まで長くスクロールし、全幅の表を横に動かす必要があった | 作業画面を上部に配置。320・390・1440pxで候補生成ボタンがページ上端から650px未満にあり、再計画と承認後にページ全体の横はみ出しがないことを確認 |
| 稼働時間の登録に日時の文字列とカンマが必要だった | 日時入力、区間追加、稼働なし、取消を実装。2区間の保存、入力エラー後の保持とフォーカス、取消時の既存データ保持を確認 |
| 差分が一文に詰まり、変更されていない値も読み直す必要があった | 担当者・開始・終了など変わった項目を表示。実際の欠勤再計画で担当者の変更を表示し、同じ農機を差分に含めないことを確認 |
| 再確認の撮影で狭い日時欄の見切れと目盛りの重なりが見つかった | スマホ幅では日時欄を1列にし、同日の目盛りは時刻表示に整理。再撮影で確認 |
| 初回の接続失敗や古い候補の拒否から復帰しづらかった | 読込の再試行と版競合時の再読込を追加。接続失敗の注入、別リクエストからの条件変更、作業員全員の稼働なしによる実際の割当不可を個別に検証 |

空の状態では、圃場・作業員・作業を登録するリンクから該当の入力欄に移動できる。テストでは圃場の登録から作業の複製、候補生成、承認まで画面の操作だけで行い、保存した割当をAPIで照合した。

## 実行結果

- 基準版で既存Chromium 7件成功。
- 改善版で型検査、単体30件、PostgreSQL 17統合7件、Chromium 12件が成功。ブラウザ試験のうち計算状態表示4件はモック。接続障害の試験は初回リクエストを1回だけ失敗させた。
- Cloud Linux、Node v24.22.1、Chromium 156、Playwright 1.58.2。PostgreSQLは既存データから隔離した一時コンテナを使用。スマホの数値はブラウザ表示幅。
- 本改善の対象は現在のローカル用途。実農場の業務、実機Safari・Firefox、長期履歴の性能、公開環境の運用には別の検証が残る。

## 再現

`npm run typecheck` と `npm test`。専用PostgreSQLの `DATABASE_URL` を指定して `npm run test:integration` と `npm run test:e2e`。ブラウザ試験は現行の模擬エンティティを入れ替えるため、完全に隔離されたDBやJSONファイルを選ぶ。画像の再生成には `E2E_CAPTURE_DIR` に出力先を指定する。

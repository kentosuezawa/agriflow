# 最小受け入れテストシナリオ（設計用・未実装）

シナリオ内の時刻はAsia/Tokyo、区間は `[start,end)`、作業は分割不可。時間粒度は暫定30分。

## SC-001 実行可能・既知の完了時刻
- 期間: 2026-11-02 09:00〜12:00
- 作業員: W1（09:00〜12:00のみ稼働）
- 圃場: F1、F2
- 作業A: F1、所要60分、開始可能09:00、期限12:00、W1が必要、農機なし
- 作業B: F2、所要60分、開始可能09:00、期限12:00、W1が必要、農機なし
- 期待: 重複なしで両作業を割り当てられ、早ければ11:00に終了できる。理論上これより前には両方完了しないため、最適なmakespanは11:00。

## SC-002 期限により解なし
- 期間: 2026-11-02 09:00〜12:00
- 作業員: W1（09:00〜12:00のみ稼働）
- 作業A/B: 異なる圃場、両方120分、どちらも期限12:00、農機なし
- 期待: W1の要求作業時間は合計4時間、稼働可能時間は3時間のため、制約を満たす計画は存在しない。十分に探索できた場合は`INFEASIBLE`。探索完了前の打ち切りでは`UNKNOWN`の可能性がある。

## SC-003 時間区間の境界
- W1に作業A [09:00,10:00)、作業B [10:00,11:00)は同時利用の競合なし。
- W1に作業A [09:00,10:00)、作業C [09:30,10:30)は競合するため不可。

## SC-004 再計画で元の確定版を保持
- 初回の確定版v1を保存。
- W1の利用可能時間を短縮し、再計画候補v2を生成する。
- 期待: 承認前にv1は変化せず、v2は候補として表示。承認後にv2が最新になってもv1は履歴に残る。

## SC-005 不正な入力
- 作業所要時間=-30分、最早開始が期限より後、存在しない圃場ID、先行関係の循環（FR-008採用時）。
- 期待: 計算実行前に検証可能な不正入力を拒否し、修正可能なエラーメッセージを表示する。

## SC-006 同種農機の排他
- 1台のトラクターM1を必要とする作業A/Bが同時刻希望。
- 期待: 同一のM1は重複不可。トラクター2台が登録されている場合は異なる実体のM1/M2に割り当て可能。

これらのシナリオは、実装後に検証コードとテスト結果を付けて初めて「検証済み」になる。
